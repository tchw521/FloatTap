# 懒人点击器 LazyTap

一个以**无障碍服务**为核心的 Android 自动点击器：能录制你的操作，也能一步步手动拼脚本，
最终收成一个悬浮球 —— 点一下跑脚本，长按选脚本，双击、三击各干各的活。

手指点酸了？让手机自己动。

---

## 一、长什么样

| 入口 | 说明 |
| --- | --- |
| **正常模式** | 打开 App 是完整的脚本管理界面：毛玻璃质感、顶部状态大卡、脚本图标、搜索、模板库、六种配色、深色适配 |
| **悬浮球模式** | 一键收起界面，只留一个小球（显示「点 / 跑 / 录」三种状态），靠手势干活 |
| **我的 → 自动触发** | 触发器规则列表：到点 / 周期 / 通知 / 插电 / 解锁自动跑脚本 |

### 底部四个 Tab（v2.0.0 起）

对齐自动精灵的分页结构：**脚本 / 市场 / 录制 / 我的**。
「运行日志 / 自动触发 / 设置 / 关于」收进「我的」子页，进去有返回条。

### 悬浮球手势

| 手势 | 默认行为 | 可在设置里绑定 |
| --- | --- | --- |
| 单击 | 跑上次运行过的脚本（没有则弹列表） | ✅ 任意脚本 |
| 双击 | 急刹车，立刻停止 | ✅ 任意脚本 |
| 三击 | 开始 / 停止录制 | ✅ 任意脚本 |
| 长按 | 弹出脚本列表面板（含停止、录制按钮） | ✅ 任意脚本 |
| 拖动 | 移动小球，松手自动贴边；静止 5 秒自己变半透明 | — |

## 二、能干的事

**动作类型（脚本由这些动作一步步拼成）**

| 动作 | 参数 | 说明 |
| --- | --- | --- |
| 点击 / 双击 / 长按 | 坐标、时长、之后等待 | 走 `dispatchGesture` 注入，不 root、不注入事件 |
| 滑动 | 起止点、时长 | 刷视频、翻页 |
| 随机点 | 中心点、随机半径 | 带抖动的点击，别那么像机器人 |
| 等待 | 毫秒 | 发呆 |
| 按键 | 返回 / 桌面 / 最近任务 / 通知栏 / 快捷设置 / 锁屏 / 电源菜单 / 分屏 | 走全局动作 |
| 输入文字 | 文本 | 直接写进当前输入框 |
| 打开应用 | 包名 | 直接拉起 App |
| 找节点并点击 | 文字、**控件 id**、**正则**、**内容描述**（可组合，全部满足才命中）、模糊/精确、只看能点的、第几个、超时 | 遍历当前界面节点查找再点，比死坐标稳 |
| 如果 🔀 | 判断文字 / 判断当前 App，成立与不成立各跳一步 | 条件分支：0=下一步，−1=收工，−2=重来一轮 |
| 计数 🔢 | 计数器加一 / 清零，涨到 N 次跳步 | 「第 3 次循环再做点别的」不用硬凑 |
| 多指 🖐 | 双指齐点 / 按住 / 捏合 / 张开 | 两条笔画同时下发，缩放、双指长按都行 |
| 找色 🎨 | 颜色、相似度、搜索区域、命中后是否点击、双向跳步 | 在屏幕或指定区域找最像这个颜色的点，比看文字更通用 |
| 比色 🌈 | 坐标、颜色、相似度、双向跳步 | 判断固定位置的颜色对不对，适合「按钮亮没亮」「血条还在不在」 |
| 找图 🖼 | 模板图、相似度、命中后是否点击、双向跳步 | 拿事先截好的小图去屏幕上找，认「跳过广告」「领红包」这类图形最省事 |
| 赋值 📝 | 变量名、值（可引用别的变量） | 把值存进变量留着后面用 |
| 运算 🧮 | 存到哪个变量、算式 | `+ - * / %`、括号、比较、逻辑，外加 `rand/min/max/abs/round/int/len` |
| 比变量 ⚖️ | 左边、怎么比、右边、双向跳步 | 两个数比大小，成立 / 不成立各跳一步 |
| 任何动作 | 重复 N 次、百分比坐标 | 精简步数、换机型不跑偏 |

**JS 脚本模式（v1.7.0）**：不想一步步拼动作就直接写代码，`if` / `for` / 函数随便用，
只有动作要加 `await`：

```js
await launch('com.example.app');
await sleep(3000);
for (var i = 0; i < 5; i++) {
  var p = await findColor('#FF6B35', { sim: 92 });   // {x, y, sim} 或 null
  if (!p) break;
  await click(p.x, p.y);
  await sleep(800 + rand(0, 400));
}
```

共 25 个函数（操作 / 识别 / 数据三类），编辑器里点「📖 能调什么」随时查。
JS 脚本用的还是**同一套动作实现**，所以变量、`{{}}` 插值、找色找图、计数器全都通用；
悬浮球、快捷磁贴、自动化触发器都能跑 JS 脚本。

**变量与表达式（v1.6.0）**：任何能填的字段都能写 `{{表达式}}`，执行到那一步才求值。
表单里点「🧩 插入变量」直接塞变量，点「= 试算」当场看这句算式算出什么，不用跑一遍脚本才知道。
内置变量有 `lastX` / `lastY` / `lastSim`（上一步找色找图的命中结果）、`loop`、`step`、
`screenW` / `screenH`、`time`、`date`、`hour`、`rand`，外加 `{{cnt.名字}}` 读计数器。
脚本编辑页有「变量（初值）」卡片，开跑前先填好初始值。

变量的作用域是**一次脚本运行**：每次开跑都回到卡片里的初值，但**循环轮次之间会保留**
（所以 `n = n + 1` 放在循环里能一直累加），两个脚本之间不共享。

**图色识别（v1.5.0）**：找色 / 比色 / 找图三个动作，配套一个**截图取色面板** ——
对着真实截图点一下就把颜色填进表单，不用手抄十六进制；模板图在截图上框一块存下来，
「找图」动作里直接下拉选名字。截图走系统 `MediaProjection`，设置页一键授权。
找图用三层金字塔搜索（1/4 粗搜 → 精修 → 定准），1080×1920 上**全屏找图约 50 ms**，
纯 Java 算法实现，**没有引入任何模型或第三方库**。

**自动化触发器（我的 → 自动触发）**：每天定时、每隔 N 分钟、收到指定通知（可限定来源 App）、
插上电源、解锁屏幕 —— 条件满足就自动跑脚本。定时走系统闹钟，通知与解锁走无障碍事件，
App 不在前台也生效，重启后自动重排；同一条规则 8 秒冷却，不会一条通知刷出一串脚本。

**条件判断（v2.0.0）**：流程控制从「跳转式」升级成「条件式」。一个动作里能放**任意多个条件**，
类型有 8 种：屏幕上有字 / 当前是某 App / 屏幕上有颜色 / 屏幕上有图 / 到了某个时间 /
随机概率 / 表达式成立 / 总是成立。**满足模式**三选一：全部满足、满足一个、满足指定个数。
还能开**重复检查直到成功** —— 条件不成立就按间隔反复试，试满上限还不成就走「不满足」那条路。
老的 `如果 / 找色 / 比色 / 找图 / 比变量 / 计数` 步号跳转**原样保留**，两套并联混用都行。

**动作分组（v2.1.0）**：把一批动作装进一个「动作分组」，再指定这组怎么跑。
四种跑法：**按顺序**（默认）、**同时来**（点击 / 长按 / 滑动合成一次多指手势一起按下）、
**打乱顺序**（每次顺序都不一样）、**随机挑一个**（每次只跑里面随机一个）。
「同时」是真的多指 —— 用 `GestureDescription` 一次派发多条 stroke，系统层面就是一次多点触控，
不是开几个线程分别点；超过系统上限（多指机型 10 条，用 `getMaxStrokeCount()` 取真实值）会截断并提示。
分组里**没有步号跳转**（子动作填的「跳到第几步」会被忽略），但「收工 / 重来一轮」照样管用。

**看得见它在跑（v2.2.0）**：脚本一跑起来，屏幕边上贴一根**可拖拽的运行浮层** ——
脚本名、跑到第几步 / 共几步、已跑多久，带「■ 停止」和「✕ 收起」。拖到哪松手就存哪；
点一下（没拖动）把 App 界面叫回来；✕ 只是临时收起，下一轮开跑自己回来。
浮层会自己把悬浮球服务拉起来（**不显示球**），跑完就退，不在通知栏赖着。
另外还能开**音量键急停** —— 跑着的时候按音量 + / − 直接刹车，这一下不去调音量
（默认关着，免得你只是想调个音量却把脚本停了；必须「开着 + 在跑 + 按的是音量键」三条同时成立才拦）。

**运行日志面板（v2.2.0 重做）**：每行带 `09:12:09` 的时间戳、**按级别着色**（普通黑 / 提醒黄 / 出错红加粗）、
顶部有「共 N 条 · X 条出错 · Y 条提醒」的统计。可以**切到「只看提醒」** ——
循环脚本跑一晚上几百行「没找到…再等等」，一档就能滤到真正要看的那几条。
还有**复制**（带时间戳，贴出去能直接看）和**清空**。
分级上很克制：只有 `动作出错 / 未知动作 / 服务没了` 算出错，
「没找到 / 跳过 / 再等等」一律算提醒，否则循环脚本的日志会红成一片没法看。

**分享码（v1.8.0）**：脚本菜单里「🔗 生成分享码」得到一串 `LT1.` 开头的文本，复制发给别人，
对方在「🏪 脚本市场」里点「📥 导入分享码」贴进去就能用；「📤 导出全部」把全部脚本打成一个码，
换手机时特别省事。导入时重名自动改名、id 重新生成，**不会盖掉你已有的脚本**。
做法是 `紧凑数组 → Deflate → Base64URL`，全是 JDK/Android 自带的东西。
50 步的脚本能压到原文的 **26%**（2057 B → 553 字符）；几十字节的小脚本因为 base64 有 33% 膨胀，
码会比导出 JSON 略长一点，这点不藏着。

**脚本市场（v1.8.0，v2.0.0 起是独立 Tab）**：内置 6 个能直接跑的完整脚本
（每日签到 / 连点器 / 刷短视频 / 跳过广告 / 游戏挂机 / 找色点击 JS 版），一键装进我的脚本再自己改。
市场是**本地内置的、不联网**——沙箱里没有能长期访问的服务器，所以没做在线市场。

**其他能力**：循环播放 / 跑 N 遍、节奏倍率、等待抖动（±25%）、找字失败即停、脚本导入导出 JSON、
运行日志、运行次数统计、开机自启悬浮球、震动反馈、快捷设置磁贴、六种主题配色、
动作与脚本按住 ⋮⋮ 拖拽排序、横屏 / 平板适配、模板图管理。

**录制（双通道）**：开启后去别的 App 随便点，内核自动捕获点击、长按、滑动、输入文字、切换应用，
并把真实操作间隔记下来（回放节奏更像人）。录制时屏幕顶部有悬浮条：停止 / 加 2 秒等待 / 撤销上一步。
  - **触点捕获**（需悬浮窗权限）：1×1 透明窗监听屏幕触点拿绝对坐标，游戏 / 自绘 UI 这类不给节点的界面也录得上
  - **无障碍事件**作为补充：负责「开应用 / 输入文字」等语义动作，并把长按语义回填给触点通道
  - 设置页可关闭触点录制，退回只走无障碍事件
录完一键存成脚本继续编辑。

## 三、怎么用（安装后 60 秒上手）

1. 安装 APK（用 `adb install LazyTap-v2.0.0.apk` 或传到手机点开安装）。
2. 打开 App → 首页顶部两个徽章会提示缺什么：
   - **开启无障碍服务**：点「开启无障碍」跳系统设置 → 找到「懒人点击器」→ 打开。
   - **授权悬浮窗**：点「授权悬浮窗」→ 允许「显示在其他应用上层」。
3. 回到 App，点右下角 ＋ 选个模板（比如「连点器」），进去按「▶ 试跑」看看效果。
4. 坐标不对？去「录制」页录一遍真实操作，比手填准。
5. 觉得碍事？设置里点「收起界面，只留悬浮球」。

> 部分 ROM（小米、华为、OPPO、vivo）会杀后台：把本 App 加入「自启动 / 后台无限制」白名单，
> 悬浮球才不会被收走。

## 四、技术架构（为什么不到 120 KB）

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 界面 / 编辑器 / 设置 | **纯 JS + HTML + CSS**（无框架），放 `assets/www` | 由 WebView 加载，体积几乎为零，改 UI 不用重编 dex |
| 无障碍内核 | 原生 Java（`TapService`） | 手势注入、节点遍历查找（文字 / id / 正则 / 描述）、事件录制、文本输入 |
| 节点匹配 | 原生 Java（`NodeMatch`，v2.4.0） | 四条件组合匹配，零 Android 依赖，可单测 |
| 脚本引擎 | 原生 Java（`ScriptRunner`） | 单后台线程串行执行，可中断，无反射 |
| 图色识别 | 原生 Java（`Img`） | 找色 / 比色 / 找图，三层金字塔搜索，纯算法无模型 |
| 表达式 / 变量 | 原生 Java（`Expr` + `Vars`） | 递归下降求值器 + `{{}}` 插值，无脚本引擎依赖 |
| 条件系统 | 原生 Java（`ScriptRunner.execCond`） | 多条件 AND/OR/N + 重复检查，与步号跳转并联共存 |
| JS 脚本 | 系统 WebView 的 V8（`JsEngine`） | 独立隐藏 WebView，JS 只管调度、动作全走原生引擎 |
| 截屏 | 原生 Java（`Capture` + `CaptureService`） | MediaProjection + ImageReader，Android 14 走前台服务 |
| 悬浮球 | 原生 Java（`FloatService`） | WindowManager 自绘，前台服务常驻 |
| 通信 | `addJavascriptInterface` 同步桥 + `evaluateJavascript` 回调 | 数据以 JSON 存内部文件，无数据库 |
| 构建 | aapt2 → javac → d8 → zipalign → apksigner | 不用 Gradle，不拉 Maven，编译 5 秒 |

**零第三方依赖**：无 androidx、无 React Native、无 Capacitor、无 OkHttp。
所以 dex 只有 119 KB，整包 117 KB，常驻内存开销就是「一个前台服务 + 一个后台线程」。
顺带一提，对标的自动精灵是 44 MB —— 它带 QuickJS、ML Kit OCR 和端上模型，我们带的是算法。

## 六、自己编译

```bash
export ANDROID_HOME=/root/android-sdk     # 需要 platforms/android-34 + build-tools/34.0.0
./build.sh 2.4.0 16                       # 参数：版本名 版本码
# 产出 out/LazyTap-v2.4.0.apk（已用 lazytap.jks 签名，storePass/keyPass: lazytap）
```

> 无网络时也能构建：整条流水线只依赖本地 Android SDK 和 JDK，不下载任何依赖。

换自己的签名密钥时用环境变量传，不用改脚本：

```bash
KS_ALIAS=mykey KS_PASS=xxx KEY_PASS=xxx ./build.sh 2.2.0 14
```

### 云端构建（GitHub Actions）

`.github/workflows/build.yml` 里配好了，推代码就自动编译。这个项目不用 Gradle，
构建链只有 aapt2 / javac / d8 / zipalign / apksigner，CI 里装个 Android SDK 就能跑，不用联网拉依赖。

| 触发方式 | 干什么 |
|---|---|
| 推代码 / 提 PR | 跑单测 + 编译签名，APK 在 Actions 页面下载（保留 90 天） |
| 推 tag（`git tag v2.0.1 && git push --tags`） | 额外发一个 Release，APK 挂在 Release 里 |
| Actions 页面手动触发 | 可以手填版本号和版本码 |

正式发布建议配两个仓库 secrets：`KEYSTORE_BASE64`（`base64 -w0 lazytap.jks` 的输出）和
`KEYSTORE_PASSWORD`。不配也能构建，只是用仓库里自带的开发密钥。

### 跑测试

```bash
bash tools/test/run-tests.sh      # 纯 Java 单测 391 项，只要装了 JDK 就能跑，不需要模拟器
cd tools/smoke && npm i && node run.js   # UI 冒烟 10 套、148 张截图，需要 chromium
```

**已知限制（未在真机跑过，沙箱无 KVM 起不了模拟器）**

- 无障碍手势、悬浮球绘制、录制事件依赖真机环境，需在手机上实际验证
- **截屏授权**必须真机点一次系统弹窗（`MediaProjection` 无法自动化授权），所以在沙箱里只能验证到
  「代码链路正确 + 画布渲染正确」，实际取到的画面是否与屏幕一致需要真机确认
- 找图对**缩放不鲁棒**：模板图是在当前分辨率下截的，换机型或改系统字体/DPI 后需重新截模板
- 条件判断里的「重复检查直到成功」是在**执行线程上原地等待**（不在主线程），
  单个条件的等待上限被硬卡在 20 秒；但开「重复检查」时整条链路的耗时是
  间隔 × 次数，写脚本时留意不要让单步占用太久
- 条件里的图色类型（屏幕上有颜色 / 有图）走的是同一张截图，同一轮里多个图色条件只截一次屏；
  但**不同轮之间会重新截图**，所以「重复检查」间隔太短（比如 50ms）时截屏开销会比较明显
- **v2.3.0 把找文字/找色/找图改成了同步轮询**（在执行线程上每 250ms 探一次），
  单次上限 60 秒。好处是超时真的生效了，代价是等待期间这一步会占住执行线程 ——
  真机上需要确认长时间等待（比如 30 秒）不会被系统判定无障碍服务无响应。
  另外找色轮询每次都重新截图，比原来「只截一帧」开销大，低端机上别填太大超时
- 变量只在脚本内有效，脚本之间不共享；想跨脚本传值目前只能靠把值写进动作字段里
- 表达式是逐个字符解析的轻量实现，`{{}}` 里嵌套 `{{}}` 不支持（要嵌套就拆成两个动作）
- **JS 脚本跑在 WebView 里，所以脚本执行期间界面这个进程必须活着**；脚本里别写不带 `await` 的
  死循环，会把 WebView 主线程卡住（跟浏览器里一样）
- JS 脚本模式会临时起一个隐藏 WebView，比纯动作脚本多占几十 MB 内存，跑完就释放；
  纯动作脚本不受影响
- 找色/找图是纯 CPU 逐像素比对，**全屏找图约 50 ms**；如果脚本里一秒找好几次会明显吃电，建议限定搜索区域
- 部分机型截屏返回的 `Image` 带 padding（`rowStride`），代码里已按 `pixelStride` 处理，但机型差异大
- 触点捕获依赖 `FLAG_WATCH_OUTSIDE_TOUCH` 的机型实现：绝大多数机型可用，个别 ROM 若不上报屏外触点，
  会自动退回无障碍事件通道（此时只能录有节点的界面，滑动请在编辑器里手动补）
- 长按识别优先用无障碍语义回填；在完全不给节点的界面里，长按可能被记成点击，需在编辑器里手动改
- 部分 ROM 需要手动加白名单，否则悬浮球会被系统回收
- 锁屏动作在 Android 9 以下无效；分屏动作在 Android 7 以下无效

## 八、合规与隐私

- 不联网、不上传、不读隐私，数据全部存在 App 内部文件里
- 无障碍服务仅用于：注入手势、读取当前界面控件文本（用于「找文字并点击」）、录制用户自己的操作
- 请只用于自己设备上的合法用途，别拿它去刷别人的量
